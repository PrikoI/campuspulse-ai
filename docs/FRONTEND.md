# Совместимый LMS-интерфейс

`python -m campuspulse.lms_server` обслуживает HTML на `/`, `/lms`, `/lms/`
и фиксированный список локальных ассетов `/lms-assets/`. `start-lms.cmd`
использует тот же сервер. Сборщик и внешние зависимости не нужны.

Интерфейс `web/lms/` восстановлен по существующим REST/SSE-контрактам:
ветка команды ссылалась на эти файлы, но не содержала их. Это минимальная
совместимая реализация; точное оформление исходного командного интерфейса
восстановить из Git невозможно.

Вход и выход используют серверные HttpOnly cookies. localStorage хранит только
тему. Роли, права и подтверждения проверяет backend. После 401 интерфейс
сбрасывает данные сессии и отменяет активный агентный запрос.
Поддержаны коллекции LMS, просмотр студентов, оценки/посещаемость, расписание таблицей, план,
универсальный каталог, личные задачи и разрешённые настройки.
Зачисление и выставление оценок используют формы с выбором студента и элемента
оценки. Остальные формы преподавателя отправляют JSON по существующему API. Новые аккаунты
студентов требуют Firebase Authentication; временно используются student1–student5.
Личные изменения
сначала показывают before/after, затем требуют отдельного подтверждения.
Агент использует настоящий POST SSE и показывает вызовы инструментов.
Ошибки базы отображаются как ошибки, тестовые учебные записи не подставляются.

Текст выводится через textContent, внешние ссылки ограничены HTTP/HTTPS.
Ключи Firebase не доступны по статическим маршрутам и не нужны браузеру.

```powershell
node --test tests/lms_frontend.test.mjs
Get-ChildItem web/lms/*.mjs | ForEach-Object { node --check $_.FullName }
```

При объединении проверены JS-модули и HTTP allowlist. Полная браузерная
проверка и работа интерфейса с реальной базой ещё необходимы.
Отсутствовавший в ветке команды `scripts/check_lms_ui.mjs` не восстановлен;
прежние упоминания запуска Chrome в HANDOFF являются историческими.
