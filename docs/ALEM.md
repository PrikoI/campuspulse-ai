# Gemma 4 через Alem

Официальная документация: https://doc.alem.ai/services/gemma4.html
Модель `gemma4`, endpoint `https://llm.alem.ai/v1/chat/completions`.
Используется существующая зависимость requests; OpenAI SDK не требуется.

## Локальный запуск

На этом компьютере ключ перенесён в приватный `.env` в корне проекта,
в переменную CAMPUSPULSE_ALEM_API_KEY. `.env` исключён из Git.
Из `.local/alem.json` ключ удалён; остались несекретные настройки.
Сервер загружает четыре настройки Alem из `.env` (provider, api_key, model,
enabled), без интерполяции и выполнения команд. Переменные окружения процесса
имеют приоритет. Остальные настройки проекта из `.env` не загружаются.
Ключ не публикуется в status, логах,
MCP, frontend и аргументах модели.

```powershell
$env:CAMPUSPULSE_LMS_REPOSITORY = 'firestore'
.\start-lms.cmd
```

Откройте http://127.0.0.1:8766/, войдите как студент и выберите режим gemma4
в панели помощника. Если сервер уже запущен, остановите и запустите его заново.
При отсутствии подключённой учебной базы модель не вызывается.
Если CAMPUSPULSE_LLM_PROVIDER ранее был задан как vertex, задайте alem явно.

Вне этого компьютера вместо локального файла используйте серверное окружение:

```dotenv
CAMPUSPULSE_LLM_PROVIDER=alem
CAMPUSPULSE_ALEM_MODEL=gemma4
CAMPUSPULSE_ALEM_ENABLED=1
```

Секрет передаётся отдельно через CAMPUSPULSE_ALEM_API_KEY. Он не включён
в шаблон конфигурации. CAMPUSPULSE_ALEM_ENABLED=0 отключает Alem даже
при разрешающем локальном профиле. CAMPUSPULSE_ALLOW_CLOUD управляет Vertex,
а разрешение Alem задаётся отдельно. Launcher по-прежнему выключает Vertex.
Для выбора прежнего провайдера: CAMPUSPULSE_LLM_PROVIDER=vertex.

## Путь запроса

HTTP/SSE → авторизованный LMS agent → Gemma → серверный allowlist MCP →
Repository → Firestore → структурированный JSON → tool message → Gemma.
API принимает engine=llm; старый engine=gemini сохранён как совместимый alias
для серверного провайдера. engine=local работает без модели.

Нет произвольных запросов к базе от модели. Идентичность задаёт сессия,
proposal для подтверждения личных записей не передаётся в модель.
Сохраняются лимиты трёх модельных шагов, восьми инструментов и 1200 выходных
токенов, проверка сессии перед каждым модельным шагом и дневной бюджет.
HTTP работает в worker thread; тайм-аут подключения 10 секунд, чтения 45 секунд.
Автоповторов и перенаправлений с ключом нет; ошибки не раскрывают тело ответа
провайдера. Содержимое private reasoning не включается в журнал или ответ.

Запросы расходуют квоту предоставленного ключа Alem. Billing Firebase,
Security Rules и облачные проекты при подключении не изменялись.

## Проверки

20 октября 2026: полный offline-набор — **134 Python-теста OK**, **5 JS-тестов OK**;
ES modules прошли node --check. Новые тесты покрывают transport, квоту/ошибки,
лимиты, авторизацию, tool response ID, allowlist и подтверждения личных действий.

Реальная проверка:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.check_alem --live
```

Прошла на предоставленном ключе: Gemma вызвала синтетический check_connection
один раз и вернула его marker в ответе. Подтверждён полный function-calling
цикл провайдера. Данные студентов и Firestore не использовались. Это не
проверка реальных учебных записей через браузер; её ещё нужно выполнить.
