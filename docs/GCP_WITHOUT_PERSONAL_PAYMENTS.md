# Облачное демо без личных платежей

Текущее решение: личный биллинг не активировать, предоплату не вносить, платный тариф не подключать. Код приложения и `start.cmd` не создают облачных ресурсов. Авторизация Google Cloud SDK на компьютере не означает согласия на оплату.

## Что спросить у организаторов

Нужен проект Google Cloud для второй задачи CampusPulse AI с включённым Agent Platform / Vertex AI API, доступом к Gemini и разрешением разместить агента в Agent Engine. Уточнить:

1. Дают ли организаторы готовый учебный проект или подходящие облачные кредиты?
2. Требуется ли личная карта или предоплата? Если да, этот вариант не подходит текущему ограничению.
3. Кто оплачивает потребление, что происходит после окончания кредитов и есть ли реальное ограничение расходов? Бюджетные уведомления сами по себе не являются жёстким лимитом.
4. Какие модель, регион и срок доступа разрешены?
5. Какие IAM-роли выдадут команде и какой существующий staging bucket можно использовать?

Переданный проект должен действительно исключать личные платежи. Наличие слов «free credit» без условий оплаты не подтверждает это.

## Подготовленные файлы

- `campuspulse/agent.py`: `CampusPulseAgent.query` для облачного runtime.
- `campuspulse/mcp_server.py`: MCP-сервер для runtime.
- `scripts/deploy.py`: проверка параметров и выключенный по умолчанию путь `ReasoningEngine.create`.
- `requirements-cloud.txt`: зависимости для будущей облачной среды.

Безопасный dry-run, который **не вызывает Google и ничего не создаёт**:

```powershell
.\.venv\Scripts\python.exe scripts\deploy.py --project ORGANIZER_PROJECT_ID --bucket gs://EXISTING_ORGANIZER_BUCKET
```

Не заменяйте заглушки личным платёжным проектом ради обхода ограничения. Даже с `--execute` скрипт завершится отказом, пока нет явного разрешения `CAMPUSPULSE_ALLOW_CLOUD=1` и совпадения `CAMPUSPULSE_ORGANIZER_PROJECT` с выбранным проектом. Это технические предохранители, а не подтверждение бесплатности сервиса.

## Последовательность только после предоставления бесплатного проекта

Проверить условия доступа и получить явное разрешение владельца проекта. Затем проверить модель/регион, установить облачные зависимости, выполнить один реальный вызов Gemini и оценить трассу. После этого выполнить развёртывание, проверить `remote.query(...)`, записать resource name и подтвердить доступность API. Минимальный веб-клиент для облачного API потребует серверного прокси с авторизацией; браузер не должен получать ADC/токены.

Реальные Gemini-вызовы, IAM для runtime, развёртывание и облачный endpoint пока **не проверены**. Сервисный аккаунт вручную и JSON-ключи не создавались. Сейчас пользовательский интерфейс вызывает только локальный агент.

На 17 октября 2026 в конфигурации указан `gemini-3.7-flash` с endpoint `global`, согласно [карточке модели Google](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-7-flash). Регион Agent Engine задаётся отдельно параметром `--location`. Перед настоящим запуском нужно проверить доступность модели и разрешённые регионы в проекте организаторов. Указание модели в конфигурации не делает запросов к ней.

## Для сдачи

Нельзя представлять локальный режим как работающий Gemini или заявлять успешное размещение в Agent Engine. Если организаторы не предоставят подходящий доступ, обсудить с ними допустимую замену облачной демонстрации. Это решение организаторов; локальное демо само по себе не выполняет обязательный пункт GCP.

Официальные инструкции: [подготовка Agent Engine](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/agent-engine/set-up?hl=en), [API ReasoningEngine](https://docs.cloud.google.com/python/docs/reference/vertexai/latest/vertexai.preview.reasoning_engines.ReasoningEngine).
