# Технический отчёт: интеграция Firestore

Дата: 20 октября 2026. Проект: CampusPulse AI.

Это отчёт первоначальной интеграции (97 тестов). Последующее улучшение JSON,
MCP и запросов описано в [FIRESTORE_JSON_REPORT.md](FIRESTORE_JSON_REPORT.md).

## Реализованная интеграция

Добавлен `FirestoreRepository`, сохраняющий существующие LMS Repository и
DataGateway интерфейсы. Выбор выполняется централизованно через
`CAMPUSPULSE_LMS_REPOSITORY=firestore`; pending и team остаются совместимыми.
Старое браузерное демо и Gemini не заменялись. Архитектура и инструкции:
[FIRESTORE.md](FIRESTORE.md).

SDK firebase-admin и клиент firebase_admin.firestore создаются лениво один раз
на процесс. Локально используется существующий JSON-ключ, в облаке — ADC.
Сам проект, база, тариф, IAM, Firestore Rules и индексы не изменялись.
Дочерний MCP-процесс получает тот же выбор репозитория, project/database и
путь credentials, а не содержимое приватного ключа. Прямой асинхронный агент
вызывает синхронный репозиторий через рабочие потоки.

Записи выполняются в транзакциях с проверкой владения курсами, связанных
документов, зачисления, уникальных пар и максимального балла. PATCH не создаёт
отсутствующие документы. Студенты читают только разрешённые курсы и собственные
оценки/посещаемость. Снимок чтения и кэш прав действуют только на один инструмент.

## Постоянные данные

После включения Firestore через API сохраняются публичные профили, courses,
enrollments, assignments, grade_items, grades, lessons, attendance, materials,
личные задачи users/{uid}/tasks и разрешённые preferences.hours_per_day.
Это поддержка постоянной записи приложением, а не утверждение, что эти коллекции
были заполнены при выполнении работы. Автозаполнения и миграции нет; реальные
облачные документы в рамках работы не читались и не изменялись.

Пароли, их хеши, API-ключи, токены, полные диалоги и tool_logs в Firestore не
сохраняются. agent_sessions и schedules не создаются: для расписания уже есть
lessons, а для долговременных диалогов сейчас нет использующего их компонента.
После перезапуска репозиторий читает те же документы; временная авторизация
и счётчики AI пока остаются в памяти.

## Агент и MCP

Восемь прежних LMS-инструментов сохранили имена и аргументы. Их чтения идут
через FirestoreRepository; get_assignments дополнительно возвращает personal_tasks.
Расписание доступно через query_data(resource=lessons), подготовка — plan_study.

Два новых инструмента обоснованы отсутствием прежнего контракта личных записей:
get_personal_data и prepare_personal_change. Подготовка не пишет данные.
Пользователь проверяет before/after и подтверждает через отдельный HTTP endpoint
actions/confirm. Подтверждение привязано HMAC к пользователю, версии и сроку
десять минут. Модель не получает инструмента подтверждения и не может менять
учебные записи/роли. Повторное применение одной подтверждённой версии идемпотентно.

## Выполненные проверки

Среда: Windows, настроенная PyCharm проектная `.venv`, Python 3.14.0,
firebase-admin 7.7.0, google-cloud-firestore 2.34.1. В настроенной PyCharm `.venv`
SDK отсутствовал; в это окружение добавлена требуемая зависимость.
Конфигурация Firebase не перенастраивалась.

| Проверка | Результат |
|---|---|
| Все существующие suites + новые тесты | 97/97, OK |
| `python -X utf8 -m scripts.check_lms` | 68/68, OK |
| Новые Firestore-тесты внутри этих прогонов | 29/29, OK |
| `python -m pip check` | No broken requirements found |
| Git ignore/local file | Ключ игнорируется и существует локально |

Полный прогон выполнялся через unittest discovery `tests` с переменными
pending/local/no-cloud и установленным audit hook deny_external_connections
из scripts.check_lms. Локальный HTTP и настоящие stdio MCP-процессы разрешены.
Журналы прогонов сохранены локально в игнорируемых `.local/all-tests.txt` и
`.local/firestore-tests.txt`.

Проверены инициализация один раз, ADC/ключ, повторное использование SDK,
сериализация Timestamp, создание/чтение/PATCH/удаление личной задачи,
пересоздание репозитория на том же тестовом backing storage, отсутствие
документа, ограничения прав/чужие курсы/студенты, конкурентные повторы зачисления,
подмена и истечение подтверждения, конфликт изменения, сохранённые настройки,
тайм-аут/квота/сбой соединения, отсутствие утечки ошибок и прежние MCP-контракты.
SDK transport замокан; проверка сохранности после реального облачного рестарта
не заявляется. Первоначальная проверка MCP обнаружила отсутствие structuredContent
в текстовом ответе SDK; тест исправлен на поддерживаемое чтение JSON content,
как уже делает существующий агент. Финальные проверки проходят.

## Проблемы и ограничения

1. Временные логины не подходят для открытого сервиса; users не является
   самостоятельной базой паролей. admin/students остаётся 503 до identity provider.
2. Общий отзыв сессий, распределённые AI-лимиты и промышленная auth не реализованы.
3. Нет готового frontend: отдельное пользовательское подтверждение требует UI.
4. Учебная схема существующей облачной базы не проверялась. Для ранее созданных
   записей другой формы потребуется согласованное отображение owner_id, uid,
   дат и детерминированных связанных id; миграция не выполнялась.
5. Контракт ограничен 100 записями/1 МБ и 24 000 символами AI-контекста.
   Универсальная пагинация работает только в ограниченном наборе, не заменяет
   промышленный серверный курсор больших коллекций. Индексы нужно проверить
   отдельно на изолированных данных; автоматически они не создаются.
6. Begin/commit/rollback используют стандартные RPC timeout/retry SDK;
   чтения — timeout=10 и retry=None, повторы конфликта транзакции — максимум три.
7. Local использует явное personal_change; свободный текст не является записью.
   HTTP-провайдер Gemini по-прежнему требует отдельного подключения.

При выборе Firestore платные функции не включаются, тариф не меняется.
Бесплатные квоты и отсутствие бесплатных TTL/PITR/backups описаны со ссылкой
на официальные условия в [FIRESTORE.md](FIRESTORE.md). При исчерпании квоты —
безопасная ошибка, сохранённые данные не заменяются локальными примерами.

## До Vertex AI Agent Engine

Нужны проверенная серверная identity, реальные пользователи и владение курсами,
распределённые сессии/лимиты, frontend подтверждения, cloud wrapper для LMS вместо
контекстного CampusPulseAgent, подключение Gemini, сервисный аккаунт с минимальным
IAM, проверка индексов и транзакций на изолированной среде, исключение ключа из
deployment-артефактов и отдельное согласование расходов. Production deployment,
переключение тарифа и включение платных сервисов в эту задачу не входили.
