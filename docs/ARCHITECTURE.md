# Архитектура и ограничения приложения

## Проблема и пользователи

Студент получает задания из разных источников и не всегда понимает, хватит ли оставшегося времени. CampusPulse объединяет собственные дедлайны с GitHub issues и предлагает учебные блоки с проверяемым расчётом. Целевая аудитория MVP — студенты программирования, которые используют GitHub и конспекты PDF/TXT.

Ценность: не только список дедлайнов, но и обнаружение перегрузки. Например, при доступных 60 минутах до дедлайна и оценке задания в 180 минут планировщик показывает 120 минут невыполнимой нагрузки. Это арифметический результат, а не вывод языковой модели.

## Локальный режим

`server.py` обслуживает статический интерфейс и HTTP API только на `127.0.0.1`. Для запроса `agent.py` валидирует контекст и создаёт MCP stdio-процесс. Клиент выполняет `initialize`, загружает контекст, запрашивает список инструментов и вызывает нужные методы. Выбор маршрута в этом режиме основан на словах запроса: материалы, GitHub или планирование.

`load_context` нужен для передачи документов через протокол, без временного файла и ограничения размера переменной окружения Windows. Этот инструмент не входит в список функций, доступных Gemini. Сервер MCP живёт только на протяжении запроса, поэтому контекст разных запросов не смешивается.

## Gemini Developer API и отдельный Vertex AI

Модель получает запрос, текущее время и схемы четырёх функций. Ответ с function calls сохраняется целиком, включая ID и thought signatures, затем программа выполняет инструменты и возвращает function responses. Максимум — 6 модельных шагов и 12 вызовов инструментов. Итоговое сообщение собирается только из текстовых частей без флага `thought`.

Журнал интерфейса содержит **действия**, аргументы, длительность, результат и ошибку. Он не заявляет доступ к внутренней цепочке рассуждений. Модель выбирает инструменты; план и вычисления остаются обязанностью `plan_week`.

Для локального приложения используется Google Gen AI SDK с явными `vertexai=False` и ключом, введённым в интерфейсе. `free_gemini.py` определяет проект ключа через официальный `keys.lookupKey`, затем проверяет `projects.getBillingInfo`. Требуется явное `billingEnabled=false`; отсутствие ответа или прав блокирует генерацию. Перед каждым шагом проверка повторяется. ADC используются только для чтения этих метаданных, не для генерации. Только модель `gemini-3.1-flash-lite`; автоматического переключения модели и провайдера нет. Ошибки Google очищаются от URL, ключей и удалённого текста ошибки.

Ключ хранится только в памяти сервера, изолирован по случайному 256-битному HttpOnly/SameSite=Strict cookie, до 12 часов. Статус и ответы не возвращают ключ. Подключение не проверяет генерацию: доступность модели и квота подтверждаются первым настоящим запросом. Без ключа запускается явно обозначенный локальный алгоритм; потеря сессии при запросе в режиме Developer возвращает ошибку, а не скрытый локальный ответ.

Отдельный `CampusPulseAgent` для будущего GCP-развёртывания использует Vertex AI (`vertexai=True`) и по-прежнему требует `allow_cloud=True`. Развёртывание выключено. Наличие ADC или ключа Developer API не снимает этот запрет. Ключ создан и его проект проверен; живые запросы не завершились из-за сетевого разрыва WinError 10054 к generativelanguage.googleapis.com. Настоящий ответ Gemini не подтверждён.

## Источники и достоверность

- Задания: ручной ввод / импорт студентом, с датой и оценкой времени.
- GitHub: текущий запрос к фиксированному домену `api.github.com`; только публичные репозитории, до 30 последних issues/PR, PR отфильтровываются. Пагинации пока нет.
- Дедлайн GitHub: только `milestone.due_on`. Поле `updated_at` не используется как дедлайн. Без даты задача не планируется.
- Оценка GitHub issue в 60 минут: гипотеза для демонстрации, показывается в интерфейсе. Для реального плана нужно уточнить оценку.
- Материалы: текст выбранных пользователем файлов, с именем источника и номером страницы при PDF. Поиск лексический. OCR и embeddings не используются.
- Учебные примеры: включаются отдельной кнопкой, видимая пометка ДЕМО, даты относительно текущего дня.

## Безопасность и приватность

У инструментов нет операций записи в сторонние сервисы, shell execution, платежей и изменения IAM. Модель не может выбрать произвольный URL или путь файла. Текст issues, задач и материалов рассматривается как недоверенные данные; system instruction запрещает исполнять инструкции из них. Это снижает риск prompt injection, но не является доказанной полной защитой модели. Доступные операции ограничены чтением.

Защиты локального HTTP: проверка Host и Origin, JSON-only POST, ограничение тела запроса 8 МБ, максимум два одновременных запроса, таймаут агента 100 секунд, CSP и запрет embedding. До 100 заданий, пяти материалов, 50 страниц PDF и 50 000 символов на материал. Сервер не открывается в локальную сеть.

Для публичного размещения потребуются аутентификация, разграничение пользователей, безопасное хранение документов, ограничение частоты запросов и контроль затрат. Текущий локальный HTTP-сервер для этого не предназначен.

## Проверяемые гипотезы развития

Пилот в учебной группе: попросить студентов вручную оценить реалистичность плана, число пропущенных дедлайнов и время на составление расписания. До пилота нет оснований заявлять рост успеваемости или процент сэкономленного времени. Далее — подтверждение оценок GitHub, интеграция календаря с отдельным согласием, импорт расписания и семантический поиск.
