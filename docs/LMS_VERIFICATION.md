# Проверка локального LMS-бэкенда

Дата: 20 октября 2026. Среда: Windows, Python 3.12.14, проектная `.venv`.
После подключения фронтенда: **50 тестов — OK** (26.789 секунды), включая провайдер
с подменёнными ADC и моделью. `start-lms.cmd --check` прошёл. `--check-vertex`
проверен на явно тестовых строках проекта/модели: configured=true, calls_enabled=false,
adc_verified=false, live_verified=false. Настройки реального проекта не подставлены.
Актуальный набор запускается из корня:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.check_lms
```

Также прошли **4 JS-теста** (`node --test tests/lms_frontend.test.mjs`):
SSE с фрагментацией UTF-8/CRLF, терминальная ошибка и обрыв, 503 с аудитом,
credentials same-origin, экранирование недоверенного текста и безопасные URL.
Синтаксис активных ES modules проверен `node --check`.

`scripts/check_lms_ui.mjs` прошёл в установленном Chrome через Playwright,
на отдельном сервере 127.0.0.1:8771 с pending/cloud=0. Проверены неверный пароль,
вход студента и преподавателя, HttpOnly cookie и восстановление после reload,
восемь студенческих переходов, честные 503 с журналом, реальный MCP SSE без
модели, переключение темы, мобильный экран 390×844 без горизонтального переполнения,
формы преподавателя без создания учебных записей, выход/истечение сессии и сброс
панели агента. Ошибок JavaScript и внешних запросов браузера не было.
Снимки мобильной и настольной страниц осмотрены; они находятся в игнорируемом build/.
Подробности повторного запуска — [FRONTEND.md](FRONTEND.md).

Набор `test_lms*.py` проверяет локальный LMS, а не прежнее самостоятельное демо.
Runner фиксирует pending/local/MCP и выключает облако; внешние соединения
из процесса проверок блокируются. Настоящие процессы MCP используют только
pending или неподключённый шаблон шлюза команды. База/SQLite, демонстрационные
учебные записи, реальные модельные запросы и облачные операции не используются.
Числовые входы калькулятора проверяют чистую арифметику и не являются данными LMS.
Тест каталога использует только описание типов полей, без записей базы.

Проверяются:

- Входы студента/преподавателя, подписанные сессии, подмена роли, срок, выход,
  ограничение неудачных попыток входа и запрет чужой идентичности.
- Все восемь стандартных коллекций для обеих ролей: 503, честные фильтры,
  executed=false, rows=null, отсутствие учебных записей в ответе.
- Проверка входных полей, методов, query-параметров, JSON/NaN/повторяющихся ключей,
  ошибочных записей/дат/интервалов до чтения источника.
- Настоящие initialize/tools/list/tools/call отдельного stdio MCP, обнаружение
  восьми инструментов, скрытие внутреннего load_session, проверка выхода
  пользователя перед следующим вызовом, отсутствие токенов в ответах.
- POST SSE с настоящим MCP: started/ready/start/access/result/complete; ошибка
  Gemini в неподключённой среде заканчивается error со статусом 503.
- Контекст страницы, универсальный каталог всей доступной базы и произвольное
  имя ресурса; новые данные не требуют добавления нового MCP-инструмента.
- Общий выбор адаптера HTTP/MCP, в том числе конкретная фабрика
  campuspulse.team_gateway:create_gateway; до реализации — 503.
- Проверки универсального запроса: доступные поля, фильтры по типам, limit,
  запрет выбора чужого пользователя/произвольных объектов-команд.
- Сбой драйвера не раскрывает его сообщение и не выдаётся за доказанное
  неисполнение: status=failed, executed=null, rows=null.
- Gemini блокируется до создания клиента и расходования счётчика при отсутствии
  базы. local не выдаётся за LLM.
- Vertex client использует явные ADC/project/location и API v1, не API-ключи.
  Проверены function response ID, реальный MCP, исключение private thoughts,
  лимиты 3/8, отсутствие повторов при 429, безопасная ошибка ADC и отказ при
  отозванной сессии до первого модельного запроса. Ни один generate_content
  не выполнен против настоящего Google endpoint; модель и ADC подменены.
- Арифметика AITU, обязательные пороги, неизвестные баллы, отсутствие выдуманных
  весов силлабуса, целевой итог и буквенные границы.
- Публичный OpenAPI и маршруты коллекций; корень не выдаёт старый фронтенд,
  старые /api/query и /api/gemini/connect не обходят LMS-контракт.
- Новый интерфейс доступен на `/`, `/lms`, `/lms/`; фиксированный allowlist
  ассетов блокирует traversal, секреты, исходники и обе архивные папки фронтенда.

Проверка launcher: `.\start-lms.cmd --check` и эквивалентный запуск модуля для
team-unconfigured успешно проверяют локальную конфигурацию без модели/базы.
Также проверен запуск отдельного процесса `campuspulse.lms_server` на свободном
loopback-порту: status и OpenAPI доступны, источник not-connected, MCP выбран,
автовызовы модели выключены. Временный процесс остановлен после проверки.

## Границы проверки

Ни одна проверка не подтверждает получение реальных учебных данных. Успешный
прогон означает корректную локальную инфраструктуру, контракты и честные отказы.
Реальная реализация DataGateway, нормализация схемы команды, права и транзакции
записей требуют проверки на базе участника команды после её появления.
Успешные ответы подключённого драйвера сейчас не имитируются наборами записей.

Не проверены живой Gemini с данными LMS, Vertex AI/ADK/Agent Engine, OAuth,
Workspace/Calendar и успешные учебные чтения/записи через фронтенд на базе команды.
Локальные cookie/SSE/ошибки интерфейса проверены на одном origin. Платные операции и
облачные ресурсы не выполнялись. PDF AITU повторно не удалось получить (502),
поэтому сохранены ранее проверенные правила 2025 без утверждения актуальности
силлабуса конкретного курса 2026 года.

`test_system.py`, `test_http.py`, `test_free_gemini.py` относятся к старому демо,
часть содержит прежние учебные примеры. Они не входят в этот запуск. Старые
SQL-тесты из build/archive-unused не импортируются и не запускаются. Полный
`unittest discover` без фильтра не является рекомендованной проверкой LMS.
