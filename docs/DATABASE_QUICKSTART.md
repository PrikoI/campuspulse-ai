# Разработчику базы: как подключиться к переходнику

Рабочий файл для участника: [`campuspulse/team_gateway.py`](../campuspulse/team_gateway.py).
Заполнить `TeamDataGateway`; агент и HTTP-сервер менять не требуется.
Универсальный контракт: [`DataGateway`](../campuspulse/lms_data.py).
Обёртка [`TeamRepository`](../campuspulse/lms_team_adapter.py) уже связывает его с API/MCP.

## 1. Подключение к своей базе

В `__init__` прочитать согласованные настройки, создать клиент реальной базы и
проверить готовность. Только после реального успеха выставить `connected=True`
и честное имя `source`. В этом задании сама база не создаётся и не заполняется.
Технология свободная: SQL, документная БД или API. Входы описывают данные, а не
команду конкретного драйвера.

`mcp_environment()` возвращает только нужные настройки этого же подключения:
API и MCP — разные процессы. Фабрика шлюза будет вызвана в обоих процессах.
Не передавать соединение/клиент через JSON; каждый процесс создаёт свой клиент.
Секреты не публиковать в схемах, ошибках, исходниках или журнале.

## 2. Каталог всей доступной базы

Реализовать `describe(actor) -> list[dict]`. Для каждого разрешённого набора вернуть:

```text
name: строка — публичное имя для команды query_data
label: строка — понятное название
description: строка — что содержат данные
fields: объект {публичное_поле: тип}
filterable: список имён полей, по которым разрешено фильтровать
```

Типы: `string`, `number`, `integer`, `boolean`, `object`, `array`.
В каталоге до 100 ресурсов, в каждом 1–100 полей. Имя ресурса/поля — до 120
символов: буквы, цифры, `_`, `.`, `-`. Имена не обязаны совпадать с физическими
таблицами. Ресурс может быть коллекцией, представлением, объединённым запросом
или методом другого сервиса. Можно анализировать реальную схему драйвером, затем
применять серверную политику доступности ресурсов и полей.

Команда просмотра каталога охватывает всю доступную текущему пользователю базу.
Она показывает **структуру и доступные наборы**, а не выгружает все записи без
границ. Студент и преподаватель могут получить разные каталоги. Не включать
пароли, токены, служебные секреты и поля, которые пользователь не вправе читать.
Каталог возвращает метаданные, не демонстрационные учебные записи.

## 3. Запрос по имени

Реализовать:

```python
def query(self, actor, resource, *, filters, fields, limit, cursor):
    # Resolve resource through your own public resource registry.
    # Query the real data source with actor scope, equality filters and limit.
    # Return only the requested, permitted public fields as JSON values.
    raise NotImplementedError  # Replace with the team's actual implementation.
```

Вход: имя из каталога; filters — объект равенств; fields — список публичных
полей или None (все публичные поля ресурса); limit — 1–100, по умолчанию 50;
cursor — непрозрачный курсор или None. Значение фильтра — строка/число/boolean/null.
Объекты и команды драйвера в фильтрах не принимаются. Фильтр допустим, только
если поле указано в `filterable` и значение соответствует типу.

Выход: **ровно** `{ "items": list[dict], "next_cursor": str | null }`.
Строки items получены из настоящего источника; имена полей соответствуют каталогу.
Вернуть не более limit, курсор следующей страницы или null. Даты/native ID
преобразовать в JSON-строки. Общий ответ до 1 МБ; для агента дополнительно действует
лимит 24 000 символов на результат инструмента. Можно уменьшить fields/limit.

`actor.user_id` и `actor.role` уже проверены сервером. Шлюз обязан применить их
к реальному запросу и к каталогу, включая принадлежность курсу/организации.
Пользователь/модель не может выбрать другого actor. Фильтры student_id, user_id,
actor, role, tenant_id запрещены; область доступа задаёт серверный код шлюза.
Курсор тоже должен перепроверяться относительно actor, фильтров и порядка.
Метаданные не заменяют проверки прав на каждое чтение.

При отключении/сбое базы — LmsError с безопасным сообщением и статусом 503.
При запрете — 403; неизвестном/недоступном ресурсе — 404. Не возвращать [] при
сбое. Обёртка сама пишет журнал имени ресурса, операции, количества и результата.
Если исключение драйвера не позволяет узнать, исполнился ли запрос, журнал
содержит status=failed, executed=null, rows=null. Это не успешное чтение.

## 4. Выбрать реализацию на сервере

```powershell
$env:CAMPUSPULSE_LMS_REPOSITORY = 'team'
$env:CAMPUSPULSE_TEAM_GATEWAY = 'campuspulse.team_gateway:create_gateway'
$env:CAMPUSPULSE_ALLOW_CLOUD = '0'
$env:CAMPUSPULSE_MODE = 'local'
.\.venv\Scripts\python.exe -X utf8 -m campuspulse.lms_server --port 8766
```

Можно указать свой `доверенный_серверный_модуль:фабрика`. Это настройка
разработчика, не строка из запроса агента. `start-lms.cmd` всегда фиксирует
pending для безопасной локальной проверки, поэтому здесь используется явная команда.
В поставленном шаблоне connected=False, методы не подключены: он вернёт 503.

## 5. Как это вызывает пользователь и агент

После временного входа через `/api/v1/auth/login`:

- `GET /api/v1/data/resources` — все разрешённые ресурсы базы с полями/фильтрами.
- `POST /api/v1/data/query` — объект с resource и необязательными filters,
  fields, limit, cursor. Ответ: items, next_cursor, resource, source,
  team_database_connected, data_access.
- В агенте команда **«Покажи доступные данные базы»** вызывает настоящий MCP
  `list_data_resources`. По выбранному имени MCP `query_data` обращается к шлюзу.
- В local можно передать `data_query` в `/api/v1/agent/query` или `/agent/stream`:
  `{message: строка, data_query: {resource: имя_из_каталога, limit: 10}}`.
  Это явная маршрутизация, без выдачи её за LLM.

Gemini в будущем сможет выбирать ресурс через эти два универсальных инструмента.
Пока реальная база/провайдер не подключены, модель не вызывается.
Чтение и каталог работают через одинаковый шлюз в HTTP и отдельном MCP-процессе.
Преподаватель может использовать универсальные endpoints API; чат агента пока
предназначен для студенческого режима.

## 6. Совместимость с предметными функциями LMS

Новые произвольные ресурсы не требуют изменений агента. Для специализированных
`get_grades`, `get_attendance`, `plan_study` нужно дополнительно отобразить данные
в стандартные имена/поля из [LMS_DATABASE_CONTRACT.md](LMS_DATABASE_CONTRACT.md).
Это адаптер смыслов для расчётов, а не ограничение универсального каталога.
Создание/изменение оценок и других записей остаётся отдельным преподавательским
API с транзакционными проверками; универсальный шлюз сейчас предназначен для чтения.

После появления настоящего источника проверить права двух разных пользователей,
состав каталогов, страницы/курсоры, сбои, размеры выдачи и фактический журнал.
Проверки без базы: `python -m scripts.check_lms` через проектную `.venv`.
