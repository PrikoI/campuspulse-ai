# CampusPulse AI — LMS backend

Локальный бэкенд LMS: студенческий режим, преподавательский API и агент с настоящими
MCP-вызовами и журналом действий. Фронтенд и база данных разрабатываются командой отдельно.

Сейчас доступны временные сессии, API, MCP stdio, JSON/SSE-журнал и калькулятор оценок
по явно введённым числам. База команды не подключена: учебные операции возвращают
503 с описанием попытки, без записей и подмены данных. `local` — алгоритм маршрутизации,
не ответ Gemini. Живой цикл Gemini и Vertex AI Agent Engine ещё не подтверждены.

## Запуск в Windows

Из корня проекта:

```powershell
.\start-lms.cmd
```

`start.cmd` также запускает новый LMS-бэкенд. Сервер слушает только `127.0.0.1:8766`.
Остановка — `Ctrl+C`. Для другого порта: `.\start-lms.cmd --port 8770`.
Готовый фронтенд сервер не раздаёт; корень возвращает описание сервиса в JSON.

- Статус: http://127.0.0.1:8766/api/v1/status
- OpenAPI 3.1: http://127.0.0.1:8766/api/v1/openapi.json
- Временный преподаватель: `admin/admin`.
- Временные студенческие сессии: `student1/student1`, `student2/student2`.

Это локальные учётные данные для разработки без учебных записей.
При перезапуске сгенерированный ключ подписи сессий меняется; войдите заново.

Проверка зависимостей без запуска сервера и внешних запросов:

```powershell
.\start-lms.cmd --check
```

На этом компьютере используйте `.venv` внутри `campuspulse-ai`, а не окружение
родительской папки. В PyCharm: интерпретатор `.venv\Scripts\python.exe`,
Run Module `campuspulse.lms_server`, рабочая папка — корень проекта.
Обычный запуск модуля также по умолчанию использует отключённый провайдер `pending`.

## Чистая установка

Нужен Python 3.11+ (проверено на 3.12). Создание окружения и установка пакетов не
подключают Google Cloud и не создают ресурсов:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\start-lms.cmd
```

Launcher не устанавливает пакеты автоматически. При отсутствии MCP запуск
завершается с сообщением; автоматического переключения на прямые вызовы нет.
`.env.example` описывает настройки, но файлы `.env` автоматически не загружаются.
Не помещайте в них API-ключи.

## Проверить без базы и платных запросов

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.check_lms
```

Проверки используют временные сессии, локальный HTTP и настоящий MCP-процесс.
Внешние соединения в процессе тестов заблокированы. Калькулятор проверяется
на числовых входах как независимая арифметика, без записей LMS.
Старые тесты самостоятельного демо и архивированная SQL-реализация не запускаются.
Подробности: [LMS_VERIFICATION.md](docs/LMS_VERIFICATION.md).

Ожидаются база команды и её адаптер, фронтенд с same-origin proxy, промышленная
авторизация, затем согласованная интеграция Gemini/Vertex AI/ADK/Agent Engine
и Google Workspace/Calendar. Личные расходы, привязка биллинга и создание облачных
ресурсов не разрешены. Сам факт наличия временных кредитов этого не меняет.

## Старые материалы

`web/`, `campuspulse.server`, `campuspulse.mcp_server`, старые ZIP/PPTX и документы
ARCHITECTURE/DEMO_SCRIPT/VERIFICATION описывают прежнее самостоятельное демо на 8765.
Они не являются инструкцией для LMS. Прежний README сохранён в
[LEGACY_DEMO.md](docs/LEGACY_DEMO.md) только для истории. SQL-файлы `.txt` в
`build/archive-unused` не импортировать и не запускать.
