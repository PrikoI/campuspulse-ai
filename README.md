# CampusPulse AI — LMS backend

Локальный веб-сервис LMS: интерфейсы студента и преподавателя, API и агент с настоящими
MCP-вызовами и журналом действий. Недостающий в ветке команды фронтенд восстановлен по API-контрактам;
постоянное хранилище Firestore выбирается настройкой. Учебные примеры не создаются.

Добавлен **Gemma 4 через Alem**: [настройка и проверки](docs/ALEM.md).
Локальный приватный `.env` хранит ключ и настройки Alem;
ключ остаётся на сервере. В панели помощника выберите режим `gemma4`.
Для данных LMS нужен настроенный Firestore, а для входа — студенческая сессия.

Также сохранён провайдер Gemini через **Vertex AI + Google Gen AI SDK + ADC**:
[настройка и границы проверки](docs/VERTEX_AI.md). По умолчанию облачные вызовы
Vertex-вызовы выключены; без подключённой базы модель блокируется. Vertex project/model задаются
отдельно и не выводятся автоматически из настроек Firestore.

Доступны временные сессии, API, MCP stdio, JSON/SSE-журнал и калькулятор оценок.
Добавлено постоянное хранилище Firestore: учебные данные, личные задачи и настройки.
`start-lms.cmd` по умолчанию использует Firestore. Для явного режима без базы
задайте `CAMPUSPULSE_LMS_REPOSITORY=pending` перед запуском.
Подключение базы не включает Gemini или развёртывание облачных ресурсов.
`local` — алгоритм маршрутизации; интеграция Vertex AI Agent Engine ещё не завершена.

**[Firestore: архитектура, конфигурация, права, подтверждения и тесты](docs/FIRESTORE.md)**.
Результаты запросов передаются структурированными JSON-совместимыми объектами
через MCP, без промежуточных файлов. [Аудит и оптимизация запросов](docs/FIRESTORE_JSON_REPORT.md)
описывают серверные фильтры, пакетные чтения и подготовленную live-проверку backend.

```powershell
$env:CAMPUSPULSE_LMS_REPOSITORY = 'firestore'
$env:CAMPUSPULSE_FIREBASE_PROJECT = 'campuspulse-ai-1021'
.\start-lms.cmd
```

Локально используется существующий `firebase-key.json` (исключён из Git).
В Google Cloud установите `CAMPUSPULSE_FIREBASE_CREDENTIALS=adc` для ADC.
Содержимое ключа не передаётся в API, MCP-аргументы или frontend.

## Запуск в Windows

Из корня проекта:

```powershell
.\start-lms.cmd
```

`start.cmd` также запускает LMS. Сервер слушает только `127.0.0.1:8766`.
Остановка — `Ctrl+C`. Для другого порта: `.\start-lms.cmd --port 8770`.
Интерфейс и API работают на одном порту. Откройте корень сервера в браузере;
отдельные Node/Vite-сервер, сборка и CORS для этого запуска не нужны.
Если уже работала прежняя версия сервера, остановите её через `Ctrl+C` и запустите заново.

- **Интерфейс: http://127.0.0.1:8766/**
- Статус: http://127.0.0.1:8766/api/v1/status
- OpenAPI 3.1: http://127.0.0.1:8766/api/v1/openapi.json
- Временный преподаватель: `admin/admin`.
- Временные студенческие сессии: от `student1/student1` до `student5/student5`.

В текущем демо форма входа скрыта: веб-интерфейс автоматически открывается как
`student1`. Существующая сессия другого пользователя переключается на студенческую.
Вход использует обычный `/api/v1/auth/login` и HttpOnly cookie; права API сохраняются.
Если подключение не удалось, интерфейс показывает ошибку и кнопку повторной попытки.
Для учебных данных по-прежнему нужны локальные настройки Firestore и credentials;
секреты не передаются при клонировании репозитория.

Это локальные учётные данные для разработки без учебных записей.
При перезапуске сгенерированный ключ подписи сессий меняется; войдите заново.

У студента есть страницы дисциплин, заданий, материалов, оценок, посещаемости,
расписания и учебного плана, а также личных задач и настроек. Преподавателю доступны
просмотр студентов и JSON-формы с примерами для восьми коллекций LMS. Все чтения
и записи идут в API; в режиме `pending` они показывают 503 с журналом попытки.
Для демо доступны `student1`–`student5`; создание других логинов требует
Firebase Authentication и не имитируется хранением паролей в Firestore.
Агент студенческого режима получает страницу и course_id, показывает SSE-этапы,
MCP-вызовы, результаты и ошибки. Отправка работ, корпоративный вход и Workspace
не реализованы. Подробнее: [фронтенд и его ограничения](docs/FRONTEND.md).

Проверка зависимостей без запуска сервера и внешних запросов:

```powershell
.\start-lms.cmd --check
```

На этом компьютере используйте `.venv` внутри `campuspulse-ai`, а не окружение
родительской папки. В PyCharm: интерпретатор `.venv\Scripts\python.exe`,
Run Module `campuspulse.lms_server`, рабочая папка — корень проекта.
Обычный запуск модуля без launcher по умолчанию использует отключённый `pending`.
Launcher выбирает Firestore, но сохраняет явно заданный `CAMPUSPULSE_LMS_REPOSITORY`.

## Чистая установка

Нужен Python 3.11+ (при объединении проверено на 3.14). Создание окружения и установка пакетов не
подключают Google Cloud и не создают ресурсов:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\start-lms.cmd
```

Launcher не устанавливает пакеты автоматически. При отсутствии MCP запуск
завершается с сообщением; автоматического переключения на прямые вызовы нет.
`.env.example` описывает настройки. Автоматически из приватного `.env` загружаются
только четыре настройки Alem; остальные задаются в окружении процесса.
Не добавляйте `.env` и ключи в Git.

## Проверить без базы и платных запросов

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.check_lms
```

Проверки используют временные сессии, локальный HTTP и настоящий MCP-процесс.
Firestore проверяется через моки SDK и внедряемое тестовое хранилище; настоящие
облачные документы не читаются и не изменяются.
Внешние соединения в процессе тестов заблокированы. Калькулятор проверяется
на числовых входах как независимая арифметика, без записей LMS.
Старые тесты самостоятельного демо и архивированная SQL-реализация не запускаются.
Подробности: [LMS_VERIFICATION.md](docs/LMS_VERIFICATION.md).

## Старые материалы

Старые `web/index.html`, `web/app.js`, `web/style.css`, модули `campuspulse.server`,
`campuspulse.mcp_server`, ZIP/PPTX и документы
ARCHITECTURE/DEMO_SCRIPT/VERIFICATION описывают прежнее самостоятельное демо на 8765.
Они не являются инструкцией для LMS. Прежний README сохранён в
[LEGACY_DEMO.md](docs/LEGACY_DEMO.md) только для истории. SQL-файлы `.txt` в
`build/archive-unused` не импортировать и не запускать.

Активный интерфейс расположен в **`web/lms/`**. Оригиналы файлов участника сохранены
без изменений в `frontend-team-source/`; мой отложенный черновик — в `frontend-draft/`.
Сервер эти две папки не раздаёт. Git commit/push автоматически не выполнялись.
